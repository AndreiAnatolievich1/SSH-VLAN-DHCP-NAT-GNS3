# Корпоративная LAN в GNS3

## Задача проекта

Построить небольшую корпоративную LAN и проверить взаимодействие базовых технологий L2/L3:

- разделить пользовательские сегменты с помощью **VLAN 10, 20 и 30**;
- организовать маршрутизацию между VLAN по схеме **router-on-a-stick**;
- централизованно выдавать адреса через **DHCP**;
- обеспечить доступ внутренних хостов во внешнюю сеть через **NAT overload (PAT)**;
- настроить удалённое администрирование маршрутизатора по **SSH**.

## Топология

![Топология корпоративной сети в GNS3](https://github.com/user-attachments/assets/d987e790-96b5-45fc-a578-dae29a94c3d6)

| Узел | Назначение |
|---|---|
| **R1 — Cisco 7200, IOS 15.3** | Сабинтерфейсы `g1/0.10`, `g1/0.20`, `g1/0.30`; DHCP relay, NAT и SSH |
| **SW1** | Магистральные `trunk`-связи с R1, SW2 и SW3; `access`-порт DHCP-сервера |
| **SW2–SW3** | Коммутаторы уровня доступа |
| **PC1–PC4** | Конечные узлы для проверки DHCP, маршрутизации и доступа во внешнюю сеть |

Внешний интерфейс `f0/0` маршрутизатора подключён к NAT-сети GNS3 и получает IP-адрес по DHCP.

## Что реализовано

- **VLAN и trunk:** сегментация сети и передача нескольких VLAN между коммутаторами и маршрутизатором.
- **Inter-VLAN routing:** отдельный сабинтерфейс Cisco IOS для каждого VLAN.
- **DHCP relay:** команды `ip helper-address` на сабинтерфейсах направляют запросы клиентов к централизованному серверу.
- **NAT overload:** ACL определяет внутренние сети, а интерфейсы разделены на `ip nat inside` и `ip nat outside`.
- **SSH:** доменное имя, RSA-ключи, локальный пользователь и `transport input ssh` на линиях VTY.
- **Troubleshooting:** описаны симптомы и последовательность проверки основных сервисов.

## Запуск

1. Установите **GNS3 2.2.56** и GNS3 VM на Ubuntu 20.04 или совместимой среде.
2. Добавьте образ **Cisco 7200** с IOS 15.3. Образ не включён в репозиторий.
3. Откройте файл `DHCP_VLAN_SSh.gns3` и при необходимости обновите пути к образам.
4. Запустите узлы и примените конфигурацию из `Config_Router.md`.
5. Настройте DHCP-сервер и проверьте сервисы по списку ниже.

> Проект предназначен для изолированной лабораторной среды. Учебные логины и пароли из конфигураций не следует использовать в производственной сети.

## Проверка работоспособности

| Проверка | Ожидаемый результат |
|---|---|
| `show vlan brief` | VLAN созданы, access-порты распределены корректно |
| `show interfaces trunk` | На магистральных портах разрешены необходимые VLAN |
| `show ip interface brief` | Сабинтерфейсы активны и имеют запланированные адреса |
| `show ip nat translations` | При обращении наружу появляются трансляции внутренних адресов |
| Запрос адреса на клиенте | Клиент получает IP, маску, шлюз и другие параметры из своего пула |
| Ping шлюза и хоста другого VLAN | Работает локальная и меж-VLAN-маршрутизация |
| SSH к адресу R1 | Удалённое подключение выполняется от имени локального пользователя |

## Диагностика типовых проблем

| Симптом | Что проверить |
|---|---|
| Клиент не получает адрес по DHCP | `ip helper-address`, доступность DHCP-сервера, пул адресов и VLAN клиента |
| Нет связи между VLAN | `trunk`, разрешённые VLAN, сабинтерфейсы и адрес шлюза на клиенте |
| Нет доступа во внешнюю сеть | `ip nat inside/outside`, ACL, маршрут по умолчанию и адрес внешнего интерфейса |
| Не работает SSH | RSA-ключи, `ip domain-name`, локального пользователя, `transport input ssh` и совместимость алгоритмов клиента |

## Итог

Проект объединяет базовые технологии корпоративной сети в одном воспроизводимом стенде и демонстрирует практические навыки настройки Cisco IOS, проверки сервисов и последовательной диагностики неисправностей.
